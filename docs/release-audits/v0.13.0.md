# Auditoría de CineUSB 0.13.0

## Device test evidence

En una LG OLED C1 con Homebrew Channel y acceso root, CineUSB 0.12.0 permite navegar por el disco NTFS, pero al intentar reproducir una película devuelve «No se pudo reconocer el formato del vídeo». Antes de esa versión, una lectura previa obligatoria produjo un error de entrada/salida (os error 5). No se dispone del código real de error de FFmpeg ni de un resultado de reproducción con esta nueva versión.

El cambio de 0.13.0 añade una alternativa de lectura posicional y separa los fallos de apertura del contenedor y del reconocimiento de pistas. La prueba automatizada de lectura local valida desplazamientos arbitrarios y fin de archivo, pero no reproduce el controlador NTFS de la televisión ni garantiza que este sea el origen del fallo.

## External compatibility reports known at release time

El informe procede del usuario de una LG OLED C1 con disco externo NTFS. La navegación está confirmada y la reproducción sigue sin confirmación de funcionamiento. No hay otros informes verificados de compatibilidad para esta corrección.

## Compatibility tiers, and what moved

Se mantiene la confirmación de detección y exploración de carpetas USB en la LG OLED C1. La reproducción de vídeos locales queda pendiente de prueba. Superar la compilación ARM no demuestra compatibilidad de lectura con el controlador NTFS ni de decodificación del contenido audiovisual.

## Known issues at release, with provenance

CineUSB 0.12.0 presenta un error genérico de reconocimiento de formato que reúne tanto el fallo de apertura del contenedor como el análisis de pistas. La lectura local con `read_at` puede fallar en un controlador que admita lectura secuencial; 0.13.0 introduce una alternativa y registra si el error persiste. Se conserva el fallo real cuando ambos métodos fallan.

No se ha probado si el vídeo reportado tiene un contenedor Matroska válido, si hay sectores ilegibles o si el fallo deriva de la integración de FFmpeg. Por tanto, la corrección no se describe como una reparación confirmada del error.

## Deliberately not done

No se escribe ni se repara el disco USB. No se suprimen errores reales de lectura, no se omiten los análisis de FFmpeg y no se asegura reproducción hasta observarla en la televisión. Tampoco se cambia la arquitectura de navegación visual.

## Release configuration

GitHub Actions construye el paquete ARM estable `com.seergi893.cineusb` con `FLAVOR=stable` y `RELEASE=1`. Los metadatos del paquete, el archivo de control y la versión Cargo se actualizan conjuntamente a 0.13.0. No se introducen nuevas llamadas de red ni permisos del sistema.
